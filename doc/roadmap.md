# KAKEN-ATLAS 技術ノート（今後の設計メモ：R9 以降）

まだ実装のない設計の合意と論点。実装が進んだものは [method.md](method.md)（方法）または [web.md](web.md)（実装）へ昇格させる。

## 1. クラスタリングと 306 区分との比較

クラスタリングと 3 指標（新規性・架橋性・成長性）の設計合意。詳細は着手時に更新する。

**距離を扱う 3 つの空間を混ぜない**：

| 空間 | 距離 | 用途 |
|---|---|---|
| 768 次元（L2 正規化） | コサイン | UMAP の近傍グラフ構築、**距離ベース指標（新規性など）の計算** |
| UMAP 10〜50 次元（min_dist≈0） | ユークリッド | HDBSCAN。距離の忠実さを捨てて密度の分解能を取る |
| UMAP 2〜3 次元 | ― | 可視化専用 |

**パラメータ選択**：306 小区分との一致度をチューニング基準にしてはならない（「区分に依存しない構造発見」と循環する）。
代わりに ①内的妥当性（DBCV）、②安定性（パラメータグリッド間の ARI でプラトーを探す、サブサンプリング・シード安定性）、
③実質的妥当性（特徴語で名付け可能か、外部アンカー、URA による評価実験）。
パラメータを先に固定してから 306 比較を行う（一致度は従属変数）。感度分析を併記し、複数粒度の提示も想定。

**306 比較**：対象は小区分を持つ基盤・若手約 15.4 万件。クロス表（純度・エントロピー）、
一致／分裂／融合／新出のパターン分類、ARI・NMI を大・中・小の 3 階層で、768 次元での区分重心と内部分散。
乖離は区分の欠陥を意味しない（審査区分は審査体制という別目的の設計）。

**挑戦的研究を 3 指標の検証台にする**（2026-09-11）。制度の趣旨（学術の体系や方向の変革・転換）から、指標が妥当なら挑戦的研究は
基盤研究より新規性・架橋性が高く出るはず。ただし「どこにあるか」「周りとの距離」では差が出ないことが分かっている
（[method.md](method.md) §11）。候補は ①同じ研究者の基盤研究（直前の課題）からの 768 次元での飛距離（研究者 ID は解析側だけで使う。
矢印として地図に描ける）、②位置でマッチングした対照に対する近傍の分野多様性（架橋性）、③挑戦的研究が多かった場所で後年に
基盤研究のシェアが伸びるか（成長性のリードラグ）、④概要の文単位埋め込みの分散。申請書の文体（「挑戦的」「従来の枠を超え」）が
埋め込みに漏れるので、タイトル＋キーワードだけの埋め込みや定型語除去の TF-IDF で併記する。

**HDBSCAN のノイズ点は捨てない**（新規性指標の候補）。所属確率（soft clustering）は架橋性の材料。
文書内部由来の架橋性として、概要を文単位で埋め込んだときの文ベクトルの分散も候補。

**クラスタ命名**：c-TF-IDF の特徴語＋代表課題タイトルから LLM で日本語ラベルを生成し人が検品する。
プレゼンテーション層であって分析層ではない（ラベルが変わっても分析結果は不変）。

## 2. 距離の定義：「所要時間」としての距離

課題間の距離はコサイン（点と点の直線）だけでなく、**隣り合う課題を渡り歩く道のり**でも定義できる。

- **測地距離**（近傍グラフの最短路、Isomap 流）: 高次元で作った k 近傍グラフの辺の長さをコサイン距離にし、最短路の長さを距離とする。
  大きな空隙をまたぐと非常に長く、大陸が切れていれば到達不能。地図上の「大きな空隙」を「近傍グラフの断絶」として数値化したもの。
- **密度を速度場とする最短時間**: 「密集地は速く、疎らな所はゆっくり、課題がない所は進めない」を、各地点の速度が密度に比例する
  最短時間（フェルマーの原理）として定義する。辺のコストを距離÷局所密度、または距離の p 乗（Fermat 距離、p≈2〜3）にして最短路を解く。
  20 万点でも 1 出発点あたり 1 秒以内。
- **ランダムウォークの到達時間・通勤時間**（拡散距離の系統）: 行きやすさ全体を測り、細い橋一本では近くならない。
  非対称（島→本土と本土→島で時間が違う）で、「メインストリームから見つけにくい」新規性の一面を表せる可能性がある。

3 指標との対応（候補）: 新規性＝全課題からの平均到達時間、架橋性＝分野 A→B の最短時間経路の通過頻度（媒介中心性）、
成長性＝年度ごとの速度場の変化で 2 地点間の所要時間が縮む領域。

## 3. 可視化と機能の構想

- **地名**: 既定は**データ由来の地名**（課題のキーワードから作る特徴語。「色の見方」の 12 方位の特徴語と同じ作り方を、
  地図上の密度の山ごとに行う）。公式区分の階層ラベル（全体で大区分、拡大で中区分、さらに小区分）は比較のための
  「行政区画レイヤ」として切替で重ねる（2026-09-11 の方針: 公開版は人が線を引く前の地形を主役にする）。
  同じ区分名が複数箇所に出るのは許容（分裂の可視化）。R9 のクラスタ命名は自然地名レイヤに載せ、二つのずれ（分裂・融合・新出）を切替で見せる。
- **自分の文書を地図に置く**: 未公開の研究計画を扱うため「文書を端末の外に出さない」が要点。ブラウザ内で Ruri 310m を実行し、
  768 次元ベクトルだけをサーバへ送って近傍 15 件を得て、その 2D 座標の重心付近に置く。小さい Ruri 版は空間が違うので代用不可。
- **時間の層**: 検索の強調に開始年度のスライダーを掛けたタイムラプス（例: 「AI」で検索して 2019→2025 を動かす）。
- **持ち込みレイヤ**: 利用者が自機関の課題一覧をブラウザにドロップして該当点を強調する（送信しない）。研究者名・機関を
  サイト側に持たない方針と、実務での必要を両立させる線引き。
- **サーバ機能**（ローカル LLM を含む計算機の到着後）: 文→近傍、課題→類似、なげなわ→要約の API。地図は静的サイトのまま
  API だけ呼び、落ちていても地図は動く設計。派生として「2 領域の間の研究像」（2 領域の重心を高次元で補間し、近傍の実例を
  LLM に読ませて言語化）、課題の組み合わせから仮想研究を生成する道具（本人の課題を固定した本人利用に限る。公開サイトには置かない）。
- **データ属性の追加**: 研究費（総額・年度別直接経費）、研究分担者（公開側では「つながりの本数」のみ）、機関、成果一覧は、
  目的が決まった時点で列単位でパーサに足す。
- **低優先の実験**: 単語を同じ空間に埋め込んで地名にする（UMAP モデルの保存が前提）、双曲埋め込み（階層構造向け）、
  球面のステレオ投影（リトルプラネット）、色覚配慮の配色（連続色の色相環に周期的な明度差を加えるトグル）。
